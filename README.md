A completely pointless project that solves [a problem nobody has ever had](/docs/motivation.md).
(TL;DR: What if you needed to generate a bit in a way that lets another person trust it wasn't manipulated, without them seeing the bit?)

![Screenshot of the frontend](https://user-cdn.hackclub-assets.com/01a16d55-ea89-77b8-87fc-13ead1f9f7c0/Screenshot%20From%202026-10-24%2011-47-48.png)

## How it works

When you submit a secret, the server takes the minute you requested (counted from `T0`) and encrypts it using the key valid in that minute (keys rotate because of legacy design principles and to prevent harm caused by potential database leak). Then, the encrypted minute is hashed (SHA 512, because it sounds cooler than SHA 256) with your secret. That hash is used as seed for a [simple pseudo-random number generator](src/safe_bit/random_generation.py) and generates a bit sequence, lowest bit of which is returned to you as the bit. Commitment is a hash of your bit and the first hash.

When you verify, the same computation is repeated, and the results are compared with the values you input in the request.

## Deployment

Copy the [compose file](compose.yaml) to your file system, adjust the variables and run it:

```bash
docker compose up -d
# Or if you use podman
podman compose up -d
```

A [Quadlet file](quadlet/safe-bit.container) is also available.

To run it, copy it to `~/.config/containers/systemd/` (don't forget about the volume file) then reload systemd and start the service:

```bash
systemctl --user daemon-reload
systemctl --user start safe-bit.service
```

If deployed using the Compose/Quadlet files, the database will be in the `safe-bit-data` Docker/Podman volume (Compose prefixes it with the project name, e.g. `safe-bit_safe-bit-data`).

To comply with the AGPL-3.0 license, if you modify the program, you must make the modified source available to its users. If you do so, you should change `SOURCE_CODE_LINK` (it affects the footer on the frontend).

Native installations are not officially supported.

### Environment variable reference

| Variable           | Required                | Default                         | Meaning                                                                                                       |
| ------------------ | ----------------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `SAFE_BIT_HOST`    | No                      | `127.0.0.1`                     | Address the server listens on.                                                                                |
| `SAFE_BIT_PORT`    | No                      | `8000`                          | Port the server listens on, between 1 and 65535. Do not change when deployed from the the OCI image.          |
| `T0`               | No                      | `2026-09-14T00:00:00+00:00`     | Date and time since which the server time is counted. The default value is the day when I started development |
| `KEY_VALIDITY`     | No                      | `10080`                         | Key rotation time in minutes                                                                                  |
| `SECRET_LENGTH`    | No                      | `32`                            | Length in bytes of secrets generated by `GET /secret`                                                         |
| `DB_PATH`          | No                      | `/var/lib/safe-bit/app.sqlite3` | Path to the database file. The whole directory needs to be writable by the service                            |
| `ALLOWED_DRIFT`    | No                      | `5`                             | How far in the past, in minutes, the request timestamp may be compared to the server time                     |
| `OPERATOR_NAME`    | Yes (for legal reasons) | `""`                            | Operator name, used in the privacy policy                                                                     |
| `CONTACT_EMAIL`    | Yes (for legal reasons) | `""`                            | Contact email to the operator, used in the privacy policy                                                     |
| `HOSTING_LOG_NOTE` | No                      | `""`                            | Hosting log note, used in the privacy policy, to indicate how messages are logged                             |
| `SOURCE_CODE_LINK` | No                      | this project's GitHub repo      | `http(s)` link shown in the page footer. Point it at your fork if you modified the code (AGPL)                |

### Footguns

- Changing `T0` after a key has been generated (shifts the real time every stored timestamp and key range refers to; new keys may overlap old ones and cause errors)
- Running `docker compose down -v` or the podman equivalent (deletes database)
- Letting the server clock drift (breaks the system; running NTP/chrony is highly recommended)
- Rate limiting endpoints, without changing `HOSTING_LOG_NOTE` (you might get into legal trouble)
- Leaving `OPERATOR_NAME`, `CONTACT_EMAIL` and (when applicable) `HOSTING_LOG_NOTE` unchanged (those values end up in the legally binding privacy policy)
- Changing `SAFE_BIT_PORT` when using OCI image (you won't be able to connect; port exposed in the image is fixed)
